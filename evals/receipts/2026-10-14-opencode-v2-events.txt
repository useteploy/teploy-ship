================================================================================
6. CONCLUSIONS
================================================================================
MEASURED:
  1. Ship's current opencode invocation HARD-FAILS on v2.0.26 (`--pure`/`--dir`
     removed): exit 1, usage text, nothing runs. Production is unaffected today
     because images/versions.json pins the 1.x line; the risk is an unpinned
     local/dev/brew binary, exactly like this machine's.
  2. On v2.0.26 the event stream is: step_start, text, tool_use (renamed from
     tool), step_finish (tool steps only; 1.x-compatible payload incl.
     tokens/cache/cost), error ({type,message,status?,response?}). Exit codes
     0/1 behave like 1.x; the final text lands in the last `text` part.
  3. Ship's parser survives v2 output but silently degrades: zero turns/usage
     for pure replies, undercounted turns for tool runs, invisible tool activity
     in the live feed (the one place a rename breaks ship outright).
  4. Session resume WORKS: caller-chosen ses_-prefixed ids persist full context
     across processes (codeword + exact prior instruction recalled). Arbitrary
     ids are rejected with a format error despite the help text.
  5. Default-model resolution with no configured model can land on an
     unauthenticated provider and surfaces as an in-stream error event (exit 1).

INFERRED:
  - The absent terminal step_finish is a v2 design change (two independent pure
    runs + the tool run's terminal step all lack it), not a flush race; but I
    did not observe multi-tool or error-mid-tool streams, so their interleaving
    is uncharacterized.
  - usage for pure replies may be recoverable from a non-stream surface (e.g.
    the session/message API) — not investigated here; the S13 adopt path needs
    a decision on whether zero-usage pure replies are acceptable (budget
    accounting would undercount) or must be fetched elsewhere.

RECOMMENDED S13 MOVE: PIN < 2 AT PREFLIGHT NOW; ADOPT v2 LATER AS A TRACKED CHANGE.
  Immediate (cheap, honest): preflight asserts the opencode version is < 2 (it
  already records the version; make >= 2 a refusal with this receipt as the
  reason). images/versions.json already pins 1.x — keep it.
  Adopting v2 later requires, at minimum:
    - command: drop --pure and --dir (run in the cwd). There is no --pure
      replacement FLAG: isolation moves to config/service level — v2 runs
      against a shared BACKGROUND SERVICE by default; --standalone gives a
      private per-invocation server (closest semantic to --pure's isolation,
      at a boot cost) or the sandbox image's config must pin plugin/MCP policy.
    - parser: accept tool_use AND tool on the live tracker's tool branch (the
      part shape is otherwise compatible: part.tool, state.input.command);
      count turns from messageID changes (step_start carries messageID) instead
      of step_finish; tolerate the missing terminal step_finish; decide the
      pure-reply usage question (accept zero vs fetch from the session API).
    - error handling: unchanged (error.message works; richer fields available).
    - session resume: use --session with caller-chosen ids REQUIRING the "ses"
      prefix (e.g. ses_ship_<runId>); this unlocks the steering/follow-up
      parity path in harness-capabilities.

VERDICT: PROOF C PASSED — v2.0.26 event contract observed end-to-end, ship's
parser compatibility measured on the real streams, resume hook proven, and the
S13 recommendation grounded in measurement.
