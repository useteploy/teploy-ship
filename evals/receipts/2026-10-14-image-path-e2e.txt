================================================================================
1. THE RIG (exact files, run verbatim from the scratch dir)
================================================================================
make-png.mjs — deterministic PNG generator, node:zlib only, no image deps.
  64x64 8-bit RGB PNG, white background, centered 32x32 pure-red square
  (R=255 everywhere; G=B=0 inside the square, 255 outside). Output:
  "redsquare.png bytes: 141 base64 chars: 188" and `file` confirms
  "PNG image data, 64 x 64, 8-bit/color RGB, noninterlaced".

wire-render.mts — OFFLINE wire proof. Drives neutron-ai's public generateText
  with an injected fetch (the adapters' documented test seam: OpenAISettings.fetch /
  AnthropicSettings.fetch) and captures the EXACT JSON body each adapter puts on
  the wire for messages: [{role:"user", content:[ImagePart, TextPart]}].
  Asserts, on the OpenAI wire: POST https://api.openai.com/v1/chat/completions
  with content = [ {type:"image_url", image_url:{url:"data:image/png;base64,<EXACT b64>"}},
  {type:"text", text:<question>} ]; and on the Anthropic wire: POST
  https://api.anthropic.com/v1/messages with content = [ {type:"image",
  source:{type:"base64", media_type:"image/png", data:<EXACT b64>}},
  {type:"text",…} ] plus a numeric max_tokens (wire requirement, defaulted by the
  adapter). Full captured bodies saved to captured-openai-body.json /
  captured-anthropic-body.json in the scratch dir.

live-vision.mts — ONE live call through the same public path:
  generateText({ model, messages:[{role:"user", content:[ImagePart, TextPart]}]}),
  WIRE/BASE_URL/MODEL/KEY from env; prints model, latency ms, finishReason,
  usage, answer; PASS = /red/i; exit 0/1. Never prints the key.

Commands (chronological, all from the scratch dir):

4. CONCLUSIONS
================================================================================
MEASURED:
  1. The UNPROVEN pair is now proven live: neutron-ai ImagePart -> adapter wire
     format -> real provider -> correct vision answer. claude-sonnet-5-5 (via
     fylun.ai) answered "Red" for the generated red-square PNG, 1.2 s,
     37 input / 4 output tokens, finishReason "stop", through the SDK's public
     generateText with no special image API. The ImagePart abstraction is
     sufficient end-to-end on the OpenAI wire.
  2. Offline wire-render: both adapters place the image byte-exactly (base64
     data URL on the OpenAI wire; base64 source block with media_type on the
     Anthropic wire; max_tokens defaulted). 11/11 assertions pass.
  3. Gateway passthrough of image-bearing bodies is covered by existing tests
     (byte-for-byte SSE + json.RawMessage field preservation), all green here.
  4. NEGATIVE, precisely characterized: the z.ai coding plan (the plan behind
     ship's zai provider) is image-blind TODAY on the Anthropic wire: invalid
     base64 is accepted with HTTP 200 (blocks never decoded), glm-5.3 reports it
     "can't view the image at the provided link", glm-4.6 hallucinates ("Yellow").
     Its OpenAI chat route exists but returns 200/{"error":{"code":"500"}}. The
     coding-plan model list has no vision variants. Any S12 screenshot routing
     that assumes zai=vision will silently produce hallucinated answers.
  5. neutron-ai's openai adapter cannot reach Zhipu bigmodel's
     /api/paas/v4/chat/completions (hard-appended /v1/chat/completions): even
     bigmodel's vision models would need an adapter/baseURL change upstream.

INFERRED (clearly labelled):
  - fylun.ai is a third-party aggregator; its claude-sonnet-5-5 is presumably
    proxied Claude with vision intact (the answer + token accounting are
    consistent with a real vision pass: 37 input tokens for image+question).
    Its retention policy is unknown — synthetic image only, per the policy note.
  - The 8826 ms glm-5.3 attempt with 359 output tokens was mostly extended
    thinking (the diagnostic response shows a "thinking" content block with a
    signature on this wire); the image itself never reached the model.
  - Docker was not needed; no claim is made about the sandbox container leg
    (that is the S12 proxy proof, out of scope here).
