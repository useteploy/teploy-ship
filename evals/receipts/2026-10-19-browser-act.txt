0. QUESTION
==============================================================================

The ```look slice launched a persistent headless Chromium inside the run's
sandbox (--remote-debugging-port=9222, src/look.ts LOOK_SESSION) and every
later look connectOverCDPs to it — but nothing told the AGENT about that
session: LOOK_HELP and the prompt never mentioned the CDP endpoint, so
agent-written Playwright launched a separate browser and ```look never saw
what the agent did. In practice the agent could observe but not act on what
it observed.

Does the fix work live — a tiny dependency-free helper baked into the
sandbox images (/usr/local/lib/ship-browser.mjs, page() + byRef(ref)) that
joins THE look session, so fill/click by snapshot ref changes the page the
next ```look observes? And does the session come back when it dies?

VERDICT UP FRONT: YES — all assertions passed live, on the image the product
boots (built by images/build.sh from THIS tree, helper baked and import-
probed at build time), inside a sealed --network none container. The same
core assertions are committed as the opt-in test src/look-live.test.ts
("browser-act live", SHIP_LOOK_LIVE=1); this receipt is the manual pass,
including the cold-start revival.

==============================================================================
2. HOW REFS RESOLVE (the contract this proof pins)
==============================================================================
byRef("e6") resolves EXACTLY the way the ```look driver resolves ref= looks
(src/look.ts lookDriverScript): render an ai snapshot on the connection
first — the aria-ref engine resolves against the last snapshot rendered
there, and an unchanged page re-mints identical refs (deterministic
traversal) — then `page.locator("aria-ref=" + ref)`, the same engine, the
same (f\d+)?e\d+ grammar, iframe refs included. A ref that is not on the
current page throws look's own error shape before any action runs.

==============================================================================
4. NOTES
==============================================================================
- AUTHORITY (the 1c question, answered live): the proof container is
  --network none — the helper started chromium, filled a form and served
  everything over loopback, and nothing could have reached the network:
  the helper inherits exactly bash's authority. The egress tier is
  enforced at the sandbox layer for every process; LOOK_SEALED and
  LOOK_OPEN_PLAN gate the ```look verb. On the open tier, agent code could
  always have launched its own chromium (one is baked in the image) — the
  helper grants no new reach, it only makes the actions land on the
  session look observes.
- Sandbox images must be rebuilt on the sandbox hosts after merge
  (images/build.sh) for the helper to exist in production; until then the
  prompt's example fails with module-not-found on old images.
- Unit-side: the repo host has no playwright, and the helper still imports
  there (playwright is imported lazily inside page()) — pinned by
  src/look.test.ts, which also pins ref-grammar/endpoint parity with
  look.ts, the shared spawn pieces, the Dockerfile bakes and the build
  context allowlist.
