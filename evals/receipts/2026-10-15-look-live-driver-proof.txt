2. PRE-FLIGHT: playwright-core@1.63.0 API VERDICT (scratch npm install, .d.ts + lib grepped, then RUN)
==============================================================================
- page.ariaSnapshot({ mode: "ai", depth, boxes }) — PRESENT in 1.63.0
  (types/types.d.ts:2101, locator variant :14517). mode:"ai" emits
  "[ref=e2]" element references and snapshots of <iframe>s. Confirmed live.
- page.getByRef() — ABSENT from 1.63.0 (no occurrence in types or lib).
  DEVIATION ADOPTED (pin NOT bumped, per the slice's rule): ref resolution
  uses the internal-but-first-class aria-ref selector engine —
  `page.locator("aria-ref=" + ref)` — which is what 1.63's own bundled
  tool backend uses for target resolution, down to validating
  /^(f\d+)?e\d+$/ and jumping to the frame for f-prefixed refs
  (coreBundle.js: _createAriaRefEngine, _jumpToAriaRefFrameIfNeeded,
  the tools' targetLocators path). The engine resolves a ref against the
  LAST ai snapshot rendered in the SAME connection
  (_lastAriaSnapshotForQuery), so the driver snapshots the page first and
  then takes the subtree — which is also the honest staleness semantic:
  an unchanged page re-mints identical refs (deterministic traversal),
  a changed page fails loudly. All three behaviors observed live (§3).
- chromium.launch({args:[..., "--remote-debugging-port=9222"]}) — Playwright
  always adds --remote-debugging-pipe for its own transport; empirically
  Chromium 155 honours BOTH (the pipe for Playwright, the port for later
  connectOverCDP turns). Confirmed live: /json/version answered on 9222
  while the launcher process held the browser, and ps shows both flags.
