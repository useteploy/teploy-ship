# UI and accessibility audit, 2026-10-03 (programme slice S10)

**What this is.** Automated evidence from `scripts/ui-audit.mjs`: a headless Chromium walk over the built dashboard on a seeded temporary file store. It is **not** user research. No person was observed, nothing here says the interface is easy to use, and a rule that did not fire only means that rule, as implemented, did not find a problem. The programme's human-observation acceptance for S10 remains **open**.

**What it checks.** At 390, 768 and 1440 px and at two 200%-zoom equivalents (a 1440 screen at 200% leaves a 720 CSS px layout viewport; a 390 screen at 200% leaves 195 px; this emulates reflow, not text-only zoom): horizontal overflow and elements wider than the viewport; targets under 24 px (WCAG 2.2 SC 2.5.8); controls and images without an accessible name; form controls without a label (placeholder- or title-only is reported separately as a warning); heading order; `lang`, title, `main` and `nav` landmarks; text contrast computed from computed styles (4.5:1, 3:1 for large text; backgrounds composited through ancestors); keyboard Tab order reaching every control, keyboard traps, and a visible focus indicator on each stop; and axe-core (wcag2a/2aa/21a/21aa/22aa + best-practice).

**Re-run it.**

```
pnpm run build && (cd web && pnpm run build)
node scripts/ui-audit.mjs --out /tmp/ui-audit     # AXE_CORE=/path/to/axe.min.js optional
# narrow: --routes /policies,/runs/run-ui --viewports 390,1440 --no-axe --debug-tab
```

Playwright is resolved from `PLAYWRIGHT_MODULE`, the repo, `web/` or `/opt/node-tools`; Chromium from `CHROMIUM_PATH` or `/opt/pw-browsers/chromium`. Nothing is installed or downloaded. Pure helpers (contrast arithmetic, heading outline, tab-order/trap analysis, aggregation) are covered by `scripts/ui-audit.test.mjs` (14 tests; negative controls were run by breaking the contrast threshold, heading-skip and target-size rules and confirming 4 tests failed).

**Seeded runs** (synthetic, written through the runtime, no worker or model): waiting on merge approval with a PR, finished with a PR, failed (push rejected), read-only scan with two findings, a follow-up chain of three runs (one still running). Per-run views audited: conversation, review, changes, verification, files, activity on the waiting, finished and scan runs; conversation only on the others.

## Defects found and fixed in this change

Each is a clear, low-risk defect; the visual identity (top navigation, dark palette, monospace type, compact controls) is unchanged apart from underlined in-text links.

| Defect | Fix |
|---|---|
| Form controls with only a placeholder or nothing (policy source, window start/end time, time zone, named users, reviewer repo/users/teams, sources "source name"); axe `label` critical on /policies | `aria-label` on each (`web/src/routes/policies.tsx`, `web/src/views/sources.tsx`) |

## Findings NOT fixed, with reasons

1. **Plain-text 404 body for unknown paths (`/no-such-page`)**: no `lang`, title, `main`, heading. Cause: the framework's built-in not-found response, not a Ship route. A fix here would be a catch-all route or response rewrite in middleware, which is not low-risk. Upstream-report candidate for Neutron (not logged from here; no `UPSTREAM_BUGS.md` in this checkout). Reproduce: `curl -H "Authorization: Bearer $T" -i /no-such-page`. Authenticated unknown *run* ids render a proper in-app page.
2. **Targets under 24 px (79 distinct elements, warn)**: the brand link (21 px tall, every page), disclosure `summary` rows (18-21 px), text links in `.row-actions`/`.task-status`/`.meta` (14-21 px tall, often 150-700 px wide), small checkboxes in labels. These are the compact controls the S10 brief and `AUDIT_OPEN.md` say to preserve. Also, the audit does not implement the SC 2.5.8 spacing exception (a small target passes if a 24 px circle on it does not touch another target), so this list is an upper bound. Needs a design decision (padding on hit areas without changing visible size) and ideally a human pass.
3. **Contrast: no failures measured**, but this check covers only static text with a solid or composited background on the pages above. Not covered: hover/disabled/active states, placeholder text, borders and icons (SC 1.4.11), text over gradients or images (none found: `unmeasuredContrast` is 0 on all pages), the open avatar/switcher menus.
4. **Heading order**: no skips on any seeded page. Not evaluated against reading quality.

## Pages and states not reached

- `/events` is a Server-Sent Events stream (never finishes loading): skipped on purpose.
- Not audited (no seeded data or not a browsable page): `/connect` and `/connect/return` (need an Akiroo handshake), `/bulletin/<slug>` (public board, needs a published note), `/oidc/*`, `/hooks/*`, `/api/*`, `/logout`, and any run in a Nucleus-backed store.
- Not exercised: the offline / live-update-disconnected state, error banners from failed form submissions, open menus and dialogs, viewer and editor roles (the audit runs as the bearer-token admin), projects/workflows with real data, long task text, non-English content, high-contrast or forced-colours mode, text-only zoom, screen readers (axe and name computation are not a substitute), touch behaviour, reduced motion.
- The keyboard check presses Tab only: it proves reachability and absence of a trap, not that each control works from the keyboard (Enter/Space/Escape/arrow handling).
- `bypassCSP` is on in the audit browser so axe can be injected; the dashboard's own CSP was therefore not exercised by this run.

## Audit-tool corrections made while building it (so the history is honest)

The first full run reported 25 errors, several of which were the tool's own false positives, not app defects, and were corrected before the numbers below: a composite `<input type=time>` takes several Tab presses (reported as a trap), focus was moved programmatically to read the unfocused style (which caused that trap), radio groups were counted as unreachable (Tab visits one per group), the walk started mid-page on a page that autofocuses (login), controls inside closed `<details>` were treated as visible, and a transparent canvas was treated as black. Each has a test or a code comment.
