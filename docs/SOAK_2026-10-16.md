# SHIP_LOOK soak — operator runbook, 2026-10-16

The first real run of the `look` perception action (S12) on the production
worker: text mode (`SHIP_LOOK`) and image mode
(`SHIP_LOOK_IMAGE_MODEL`) on, one scratch-repo run that forces both, then
read the evidence and decide whether they stay on. Both flags are
default-off and materialised into the run input at enqueue — only runs
enqueued after the redeploy get the action, and replays return recorded
snapshots without launching anything (docs/DEPLOY.md, env table).

Evidence this rests on, all local, none of it production:

- `evals/receipts/2026-10-14-egress-proxy-browser-proof.txt` — the
  in-sandbox Chromium session boots through the run's egress proxy, CDP on
  loopback, flags pinned.
- `evals/receipts/2026-10-15-look-live-driver-proof.txt` — the text look's
  generated driver against the real image (a11y tree, `[ref=eN]` labels).
- `evals/receipts/2026-10-15-look-image-live-proof.txt` — the image look's
  capture -> artifact -> digest round-trip, real pixels proven. It names
  this step: wiring `SHIP_LOOK_IMAGE_MODEL` against the z.ai plan "is the
  first soak once a worker runs image mode."
- `evals/receipts/2026-10-14-image-path-e2e.txt` — the ImagePart survives
  ship's adapters and the gateway byte-for-byte; the z.ai plan's models were
  image-blind on the Anthropic wire as of 2026-10-14, and the flash model's
  decode is the 2026-10-15 owner decision below.

Preconditions (check before the window): the deploy is a build carrying the
S12 slices (PRs #75/#78 and this branch's guard); the worker's
`SHIP_SANDBOX_IMAGE` is the node image — Chromium plus the pinned
playwright 1.63.0 from `images/versions.json` — or every look dies at
browser boot.

## 1. Stop, then back up

The backup is only consistent after the coordinated stop it itself demands:
ship web, ship worker and the nucleus engine. Let it print the commands,
run them (workers this box's docker cannot see — systemd units — are stopped
by their own mechanism; the attestation flag below covers that), then:

```sh
scripts/ship-backup.sh backup --label pre-look-soak-2026-10-16 --i-stopped-writers
```

Read the output: it ends with the archive path, byte count and sha256, and
the verify/rehearse commands. `verify` is cheap; run it. Retention is the
operator's — nothing here deletes a backup.

## 2. The old workers stay stopped (NA-01)

A worker's environment is baked in when its container is created; a
`docker restart` (or `docker start`) of the OLD container reuses that
captured environment, so a secret changed in step 3 reaches the worker only
when the container is recreated — which the deploy in step 4 does. Do not
"just restart" a worker to pick up flags; it will come back without them
and say nothing about it.

## 3. Set the secrets

```sh
teploy secret set SHIP_LOOK=1
teploy secret set SHIP_LOOK_IMAGE_MODEL=zai/glm-5.3-flash
```

The model id must be the gateway-routed form, `provider/model`. teploy-gateway
routes every configured model by that shape and rewrites the prefix; its
`zai` builtin is the z.ai coding plan's Anthropic-compatible surface
(`api.z.ai/api/anthropic`, `ZAI_API_KEY`; teploy-gateway
`internal/gateway/config.go`, README "All configured models by
`provider/model` id"). Ship resolves `SHIP_LOOK_IMAGE_MODEL` through the
same path as `SHIP_MODEL`, and `zai/` is one of its Anthropic-wire prefixes
(`src/model-id.ts`), so `zai/glm-5.3-flash` — not the bare `glm-5.3-flash`
— is the value that reaches the right provider.

Where to confirm before relying on it:

- The owner decision, with the live decode test through the plan's flash
  model: `docs/DECISIONS_OPEN_2026-10-04.md`, "Decided 2026-10-15"
  (Decision 3, the screenshot class only).
- The gateway actually carries the provider: its deployed config lists
  `zai` with a key, or the builtin applies and `ZAI_API_KEY` is set on the
  gateway host (teploy-gateway `internal/gateway/config.go`) — else the
  pixel turn 401s.
- After the run, the router's own truth: `teploy-gateway usage` aggregates
  per project/provider/model — the soak's image turns must appear there as
  the flash model.

## 4. Redeploy

```sh
teploy deploy
```

This recreates web + worker with the new environment (secrets persist
across deploys). Watch the worker come up and report to the fleet before
enqueueing anything.

## 5. The scratch run

A throwaway repo with an allowlist entry for one stable page — the default
`allowlist` tier is what D3 accepts for a browser; the sealed tier refuses
before the step, and `open` without plan review refuses too:

```sh
teploy-ship project set <scratch-repo-url> --egress-allow example.com:443
```

Suggested task (substitute freely; it needs one a11y-readable fact and one
pixel-only fact, so both modes must actually run):

> Add LOOK-NOTES.md with exactly two lines: (1) the `<h1>` text of
> https://example.com and the URL its "More information..." link points at,
> read with a ```look; (2) the page's dominant background colour, taken with
> ONE ```look image=on — the colour is styling and exists only in the
> screenshot, not the accessibility tree. Quote both lines in your final
> message.

```sh
teploy-ship enqueue "<task text>" --repo <scratch-repo-url>
```

The known-good answers make grading a glance: h1 "Example Domain", the link
-> https://www.iana.org/domains/example, background white.

## 6. What to read

Run page first, worker logs second:

- **Look steps** — the run's Activity/event log shows `turn-N-look` (text
  snapshot) and `turn-N-look-image` (screenshot) as recorded steps. The
  image step's result carries the artifact id, sha256 digest and byte
  count; the conversation shows the `[screenshot: sha256:...]` note beside
  the framed text.
- **Refusals** — they arrive as framed observations to the agent, each saying
  exactly which knob it wants, and are visible in the conversation view:
  `REFUSED: ... SHIP_LOOK_IMAGE_MODEL` (image gate: not set, or the worker
  lacks the wiring), the per-run cap message naming `SHIP_LOOK_IMAGE_MAX`,
  the sealed-tier and open-without-plan refusals (network-tier decisions,
  not run-fixable), and the stale-`[ref]` message asking for a fresh
  snapshot. A refusal here is the design working; what the soak decides is
  whether any of them fired when the configuration said it should not have.
- **Image routing** — the run's recorded input (`lookImage.model` =
  `zai/glm-5.3-flash`), the `turn-N-look-image` step above, and the
  model's next turn: it must answer with the pixel-only fact. Then
  `teploy-gateway usage` — the flash model's request count should move by
  the number of image looks (1 for this task; the cap is 3 per run).
- **PR check (D4)** — the pull request must carry NO screenshot:
  look-image artifacts are a class `uploadPrAsset` refuses outright. A
  rendered image on the PR is a defect, not a nicety.
- **Worker stderr** (`docker logs <worker>`) — browser boot failures,
  executor errors, artifact-store faults. The page content itself is
  untrusted and framed; the logs should show no unframed page text.

## 7. Flip criteria

Leave both flags on when, and only when:

- the scratch run (ideally 2–3 by different tasks/repos) finishes clean:
  diff is exactly the asked file, both facts correct, PR opened with no
  image attached;
- no unexpected refusals: nothing sealed/open-tier (the config was right),
  no `SHIP_LOOK_IMAGE_MODEL` refusal on an image turn, stale-`[ref]`
  messages recovered by a re-look rather than looped;
- spend is sane: single-digit flash-model requests per run in the gateway's
  usage, and the Spend page accounting is what you expect — if `zai/` is
  not in this deployment's `SHIP_QUOTA_MODEL_PREFIXES`, the flash model
  falls to conservative highest-rate pricing; either accept that knowingly
  or set the prefix and redeploy.

Record the outcome as a receipt (`evals/receipts/2026-10-16-look-soak.txt`:
run ids, the log lines that decided it, spend numbers), and update
`AUDIT_OPEN.md` if anything refused that should not have.

## 8. Rollback

```sh
teploy secret rm SHIP_LOOK
teploy secret rm SHIP_LOOK_IMAGE_MODEL
teploy deploy
```

Same NA-01 rule: the secrets land when the deploy recreates the worker.
Nothing else needs cleaning — runs already enqueued with `look` in their
input replay exactly as recorded (that is the materialisation rule, not a
gap), and look-image artifacts age out under the screenshot retention. If
the store itself is in question, the step-1 backup is the recovery path
(`scripts/ship-backup.sh restore` into isolation, then `rehearse`, never
unpack over the live store).
